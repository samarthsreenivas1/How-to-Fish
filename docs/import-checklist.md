# Studio import checklist — 7-island revamp

The one manual step the overnight build could not do for you: re-importing the
regenerated `.glb`s into Studio and re-exporting `assets/Assets.rbxm`. Until
this is done the game RUNS but shows fallbacks: new islands are "coming soon"
in the travel menu, ranged weapons and the boat use their procedural shapes,
new creatures use recolored stand-ins. Nothing errors — it is all the
established missing-mesh behavior.

Follow assets/README.md's import steps (glTF import, keep collision fidelity,
replace under ReplicatedStorage/Assets keeping the EXACT names, then
right-click Assets → Save to File… → assets/Assets.rbxm, restart rojo serve,
commit the .rbxm).

**Or run the batch script:** `tools/studio_import.lua` automates every row
below — paste it into Studio's Command Bar (View → Command Bar), read the
DRY_RUN plan it prints, flip `DRY_RUN = false` at the top, paste again. It
imports all 21 glbs, renames only the top-level groups, applies each row's
CollisionFidelity, sets the three genuinely-manual Neon parts, never deletes
anything (replaced groups become `<Name>_old_<timestamp>`), and prints a
verification report against this ledger. The Save-to-File export and rojo
restart at the end are still yours.

## Boss packs: the glowing parts, and which are your job

Read this once; it applies to every `<Boss>Pack` row below. Studio's glTF import
lands every MeshPart on flat `Plastic`, so a part that is meant to glow has to
have its Material set to `Neon` by somebody.

For ARENAS that somebody is the game. `BossArenaService.placeAuthored` sets
`Enum.Material.Neon` on every part of an arena whose OBJECT NAME contains `Glow`
(the contract is spelled out in its comment block at ~line 84). That is why no
arena row ever asks you to touch a material.

BOSS PACKS get no such rule - they are cloned by their `<Boss>BodyController`,
which copies the part exactly as imported, so `Glow` in the name buys nothing on
this side. Several controllers now assert their own fight-critical glow just
after the clone (Pyrelisk's `_Core`/`_Seam`/`_Eyes`, Gnashroot's `_Core`,
Brinejaw's and Rimefang's `_Eyes`, and Noctyss's stalk bulb, which the fight
lights and douses), and for those the import setting is harmless but not needed.
Wrack's controller goes one better and runs the `Glow` name rule itself, so
every emissive part of `WrackPack` is covered too. The ones that genuinely
depend on you, as of 2026-08-30: `KrakenPack`'s `Kraken_Eyes`/`_Sucker` and
`NoctyssPack`'s `Noctyss_Gullet`.

At the keyboard the rule is simply: set what a row asks for and nothing it does
not - a redundant Neon costs nothing, while the parts a row says must NOT be Neon
(`Kraken_Pupil`, `CreaturePack`'s `Gnashroot_Eyes`, and `GnashrootPack`'s
`Gnashroot_Eye` - whose fourteen instances the boss rig switches between dark
plastic and Neon itself) are dark on purpose. (When a glow is something
the fight depends on, the lasting fix is a line in the controller, the way
Pyrelisk does it, rather than an import step someone has to remember.)
