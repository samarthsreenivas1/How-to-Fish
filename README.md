# How to Fish

A Roblox fishing-and-melee game: cast off a dock, play a reel minigame to
land what bit, then fight it. Catches drop materials, materials craft better
rods and weapons, better gear reaches rarer water - including a volcano
whose crater lake you fish from the rim, and an island boss you summon with
a bait crafted from every creature you have beaten.

Built with [Rojo](https://rojo.space): the game is generated from `src/`
every time you connect, so there is no place file to pass around. The 3D
assets are generated too - Blender scripts in `assets/`, not hand-sculpted.

---

## Quick start

**macOS:** follow [`docs/RUNNING-ON-MAC.md`](docs/RUNNING-ON-MAC.md) - it is
the step-by-step version, including the three things that are easy to miss.

**Windows:**

```powershell
aftman install                 # rojo 7.7.0, StyLua 2.5.2, selene 0.31.0
selene generate-roblox-std     # once; the std file is generated, not committed
rojo plugin install            # the Studio plugin; restart Studio after
rojo serve
```

Then in Studio: new Baseplate place -> **Plugins** -> **Rojo** ->
**Connect** (`localhost:34872`) -> **Play**. Output should read
`[Boot] 15 service(s) online.` and `[Boot] 23 controller(s) online.`

**Sign into Studio with the Roblox account that uploaded the meshes.**
`assets/Assets.rbxm` holds that account's mesh ids; on another account every
island, rod, weapon and creature falls back to plain parts.

## Layout

```
src/Shared/    content data (creatures, rods, weapons, bait, bosses,
               materials), config (world, islands, tuning), the remotes
               registry, and modules both sides share (cast aim, reel
               math, model builders)
src/Server/    15 services - world + island bounds, creatures and the
               boss engine, fishing, combat, progression, crafting, bait,
               inventory, drops, admin
src/Client/    23 controllers - first-person viewmodels, the minigames,
               combat feedback and VFX/SFX, and the UI kit in Client/UI
               (Theme, Kit, Describe, ItemDetail) that every menu is built from
assets/        the *_gen.py Blender generators, their .glb output, and
               Assets.rbxm (the Studio import - NOT regenerable, see below)
docs/          per-feature specs and the macOS setup guide
context.md     the handoff document: state, binding decisions, gotchas
```

## Before you commit

```bash
stylua src && selene src && rojo build --output /tmp/check.rbxlx
```

All three must be clean. **A clean lint is not proof the game boots** - a
file saved with a UTF-8 BOM passes all three and still makes Luau refuse to
parse it, which takes the whole game down. `context.md` (Gotchas) has that
one and the others that cost real time.

## Two things that cannot be rebuilt from source

- **`assets/Assets.rbxm`** - the result of importing the `.glb` files into
  Studio. It carries mesh ids uploaded to a Roblox account; no script can
  reproduce it. Never delete it, and re-export it after re-importing any
  regenerated mesh (`assets/README.md` has the walkthrough).
- **Uploaded image ids** in `src/Shared/Config/Ocean.luau` and
  `Lava.luau` - the water and lava textures, uploaded once from
  `assets/*.png`.

Everything else - every island, creature, rod and weapon mesh - is
regenerated by re-running the matching `assets/*_gen.py`.
